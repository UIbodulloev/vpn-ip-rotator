# Релей

Воркер проксирует агента на три API и больше никуда. Нужен потому, что с
российского хостинга `api.telegram.org` недоступен, а доступность
`api.upcloud.com` оттуда не гарантирована.

## Развёртывание

```bash
npm install -g wrangler
wrangler login

# ключ, которым агент представляется релею
openssl rand -hex 32                  # запомните значение — оно пойдёт в RELAY_KEY агента
wrangler secret put RELAY_KEY         # вставьте его же сюда

# впишите свой домен в routes внутри wrangler.toml, затем
wrangler deploy
```

Проверка: `curl -H "X-Relay-Key: <ключ>" https://relay.example.net/healthz` → `ok`.

## Два обязательных условия

1. **Отдельный домен.** Не тот, на котором висит VPN. Иначе блокировка домена
   выносит разом и VPN, и канал управления, которым эту блокировку чинят.
2. **Не `*.workers.dev`.** Этот домен в России регулярно режут — нужен свой,
   с Worker Route и включённым проксированием (оранжевое облако).

Второй релей на втором домене стоит ноль и добавляется в `RELAY_URLS` через
запятую: агент перебирает адреса по очереди и запоминает сработавший.

## Что видит Cloudflare

TLS терминируется на их edge, то есть токены UpCloud, Cloudflare и Telegram
проходят через воркер в заголовках. Свой DNS вы Cloudflare уже доверяете, так
что порог доверия не меняется — но знать об этом стоит. Сам воркер ничего не
хранит и тела запросов не логирует.
