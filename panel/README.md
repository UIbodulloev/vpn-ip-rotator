# Панель 3X-UI на VPN-сервере

`client.py` живёт на VPN-сервере в `/opt/panel/client.py` и управляет клиентами
VLESS+Reality. Бот вызывает его по SSH (`rotator/bot.py`, `PANEL_SCRIPT`) —
панель слушает только `127.0.0.1`, наружу её порт не открыт.

```
client.py list          # клиенты, трафик, состояние
client.py add <имя>     # создать и выдать ссылку vless://
client.py link <имя>    # ссылка существующего клиента
client.py del <имя>     # удалить
client.py sync          # заставить ядро перечитать клиентов из базы
```

## Зачем `sync` и метка «НЕ В ЯДРЕ»

3X-UI 3.11 применяет добавление клиента **через core API, не перезаписывая
`/app/bin/config.json`**. Пока ядро не перезапускалось, клиент работает. Но
любой следующий перезапуск ядра (например, удаление другого клиента — панель
пишет в лог `hot apply: clients left the config, restarting`) читает файл, где
нового клиента нет. Результат: ключ выдан, в панели виден, в базе `enable=1`,
а на телефоне **timeout**.

Поэтому `add` и `del` после правки вызывают `restartXrayService` и ждут, пока
UUID действительно появится (или исчезнет) в живом конфиге. `list` сверяет базу
с ядром и помечает расхождение как `НЕ В ЯДРЕ` — этот же случай виден в боте.

Проверить вручную:

```sh
docker exec 3x-ui cat /app/bin/config.json \
  | python3 -c 'import sys,json; [print(c.get("email"), c.get("id")) for i in json.load(sys.stdin)["inbounds"] for c in (i.get("settings") or {}).get("clients") or []]'
```

## Жалобы правообладателей и BitTorrent

Жалоба на нарушение авторских прав приходит не вам, а владельцу IP — UpCloud,
и он вправе приостановить сервер. Поводом обычно оказывается не сам сервер, а
клиент VPN, качающий торренты: в рой попадает выходной адрес сервера.

`p2p-block.sh on|off|status` вешает отдельную цепочку `P2PBLOCK` в `DOCKER-USER`
(трафик клиентов WG) и `OUTPUT` (исходящее от xray). Ловит рукопожатие
BitTorrent, запросы DHT и обращения к HTTP-трекеру.

**Чего он не умеет.** Клиенты BitTorrent поддерживают шифрование протокола
(MSE/PE), и тогда сигнатур в пакете нет — такой трафик пройдёт. Это снижение
риска, а не гарантия. Надёжно помогает только знать, кому выданы ключи.

`status` показывает счётчики по каждому признаку — сразу видно, блокируется ли
что-нибудь на самом деле.

## Остальные файлы в `/opt/panel`

| Файл | Что | Права |
|---|---|---|
| `credentials` | логин панели и `PANEL_API_TOKEN` | 0600 |
| `reality-params.env` | host, порт, pbk, sid, sni для генератора ссылок | 0600 |
| `backup/amnezia-xray-server.json` | конфиг Amnezia до переноса на 443 | — |

Приватного ключа Reality в `reality-params.env` нет намеренно: генератору
ссылок и Worker'у он не нужен.

## Версия ядра Xray и клиенты на sing-box

С Xray **26.9.8** сервер REALITY отвергает ClientHello, в котором нет
`X25519MLKEM768` перед обычным `X25519`, и молча отдаёт клиенту настоящий
сертификат сайта-прикрытия. Клиенты на ядре sing-box (сам sing-box, Hiddify,
Karing) этот ключевой обмен вырезают и получают `reality verification failed`.
Клиенты на ядре Xray — v2rayNG, Streisand — работают.

Проверка связана с тем, поддерживает ли сам сайт-прикрытия постквантовый обмен:
`xray tls ping <хост>` печатает `TLS Post-Quantum key exchange`. Почти все
крупные сайты уже отвечают `true`.

`xray-core.sh` откатывает ядро, не трогая панель:

```
/opt/panel/xray-core.sh status
/opt/panel/xray-core.sh pin 26.6.27
/opt/panel/xray-core.sh restore
```

Прежний бинарник сохраняется внутри контейнера, поэтому `restore` возвращает
всё как было. Обновление образа 3x-ui вернёт ядро из образа — после него `pin`
надо повторить. Это временная мера: когда правка доедет до sing-box, ядро
надо вернуть, потому что откат отключает и остальные исправления.

## Зеркало подписок на VPN-сервере

Подписку раздаёт воркер на Cloudflare, но часть мобильных операторов режет
диапазоны, где живут бесплатные зоны Cloudflare (`104.21.x`, `172.67.x`):
у человека не открывается ссылка, хотя сам VPN работает. Адрес VPN-сервера у
него работает заведомо — через него идёт туннель. `sub-mirror.py` раздаёт то
же самое отсюда.

Содержимое не генерируется заново, а забирается у воркера и кэшируется на час.
Правила маршрутизации должны жить в одном месте: две копии логики разъедутся,
и разъедутся молча. Воркер недоступен — отдаётся последняя удачная копия с
заголовком `X-Mirror-Stale: 1`.

Порт 443 занят Xray с Reality и трогать его нельзя — на нём держится вся
маскировка под обычный HTTPS. Поэтому зеркало на **8443**, а сертификат
Let's Encrypt выпускается через порт 80.

Сначала DNS: **CNAME** `sub2.<домен>` → `vpn.<домен>`, **серым облаком**.
Именно CNAME, а не A: при ротации адреса имя уезжает следом само.

```bash
./sub-mirror-install.sh sub2.example.net https://sub.example.net
```

Скрипт проверяет, что имя указывает на этот сервер и что воркер отвечает, —
и только потом ставит certbot, выпускает сертификат, пишет systemd-юнит и
запускает службу. В конце сам дёргает подписку снаружи и разбирает её как
JSON: молча поднявшаяся, но отдающая мусор служба хуже упавшей.

Дальше адрес указывается боту: ⚙️ Настройки → Генератор подписок →
`https://sub2.example.net:8443`.

Проверки без запуска службы:

```
/opt/panel/sub-mirror.py selftest     воркер отвечает? сертификат на месте?
journalctl -u sub-mirror -n 50        что было
```

Сертификат служба перечитывает сама раз в час, поэтому продление certbot'ом
перезапуска не требует.

## Hysteria2: туннель по UDP рядом с VLESS

У мобильных операторов в России душат длинные TCP-соединения к иностранным
адресам: VLESS подключается и ползёт, причём одинаково в разных приложениях на
разных движках. UDP при этом проходит — AmneziaWG на своём порту работает на
полной скорости. Измерено на этом сервере: через туннель VLESS локально
**93 МБ/с**, то есть ни ядро, ни шифрование, ни фильтр BitTorrent ни при чём.

Hysteria2 — это QUIC поверх UDP, а обфускация `salamander` превращает его в
бесформенный UDP: для оператора он неотличим от того же AmneziaWG. При этом
сохраняется всё, ради чего выбирали VLESS: одна ссылка-подписка, белые списки,
домен вместо адреса — переезд сервера людей не касается.

```bash
./hysteria2-install.sh vpn.example.net 39443
cd ../subs && ./deploy.sh sub.example.net     # подхватит порт и пароль обфускации
```

Установщик проверяет домен и свободный порт, скачивает sing-box, выпускает
сертификат (порт 80), собирает конфиг из клиентов панели и поднимает службу.
Пароль обфускации генерируется один раз и при повторном запуске не меняется —
иначе отвалились бы все выданные профили.

**Пользователи берутся из панели 3x-ui:** пароль человека совпадает с его UUID
в VLESS. `client.py add` и `del` вызывают `hy2-sync.py` сами, так что выдача и
отзыв по-прежнему делаются одной командой. Если Hysteria2 не установлен, хук
молча ничего не делает.

В подписке появляется `urltest`: телефон пробует оба протокола и берёт живой.
Hysteria2 стоит первым, `tolerance` большой — чтобы выбор не прыгал на мелкой
разнице задержек. Нет Hysteria2 на сервере — подписка остаётся с одним VLESS,
как была.

```
/opt/panel/hy2-sync.py --dry-run     посмотреть конфиг, ничего не трогая
journalctl -u sing-box -n 50         что было
```
