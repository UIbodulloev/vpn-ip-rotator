# vpn-ip-rotator

Меняет IP-адрес VPN-сервера на UpCloud, когда его заблокировал ТСПУ. Замечает
блокировку сам, отличает её от блока протокола, переписывает DNS-запись и
рапортует в Telegram. Управление целиком из чата.

Написан под связку **Amnezia (VLESS+Reality и AmneziaWG) + UpCloud +
Cloudflare**, но привязан к API провайдеров, а не к конкретному VPN.

> **Конфиги клиентов не меняются никогда.** Ни при смене адреса, ни при переезде
> в другую страну. Это главное свойство всей конструкции — при условии, что вы
> один раз прописали в конфигах домен вместо IP (см. [Шаг 4](#шаг-4-клиенты--один-раз-до-первой-ротации)).

## Быстрый старт

```bash
# 1. Релей на Cloudflare (нужны только curl и python3)
cd relay
export CF_DEPLOY_TOKEN=$(cat ~/.cf-deploy-token)
./deploy.sh relay.example.net

# 2. Агент на российском сервере
git clone https://github.com/UIbodulloev/vpn-ip-rotator.git
cd vpn-ip-rotator && sudo ./install.sh

# 3. Остальное — в чате с ботом
#    /setup  → четыре шага, печатаете только два токена
#    /check  → проверка доступов
#    /plan   → что именно сделает каждый режим
```

## Как это устроено

Три ограничения объясняют, почему всё именно так.

**1. Сервер не видит собственную блокировку.** Из Европы он доступен всегда.
Блокировка существует только со стороны России, значит наблюдатель обязан
стоять в России. Это и есть роль вашего российского сервера.

**2. С российского хостинга не работает Telegram API.** Бот не может ходить в
`api.telegram.org` напрямую, и доступность `api.upcloud.com` оттуда тоже не
гарантирована. Поэтому агент ходит наружу через маленький воркер на Cloudflare.

**3. Смена основного IP требует остановленного сервера.** В документации
UpCloud: *«If a MAC address is specified, the server … must be in `stopped`
state»*, а удаление сервера — тем более. Скрипт, живущий на самом VPN-боксе,
остановил бы сам себя на втором шаге из семи. Оркестратор обязан быть снаружи.

```
┌──────────── Россия ────────────┐   ┌── Cloudflare edge ──┐   ┌──── UpCloud ────┐
│ ваш существующий РФ-сервер     │   │                     │   │                 │
│                                │   │  Worker «relay»     │   │  VPN-сервер     │
│  vpn-rotator (systemd)         │   │  ─ /tg  → telegram  │   │  xray :443      │
│   ├ пробы ────── прямой TCP ───┼───┼─────────────────────┼──▶│  awg  :35206    │
│   ├ бот  ───┐                  │   │  ─ /uc  → upcloud   │──▶│  ключей нет     │
│   ├ движок ─┼── HTTPS через ───┼──▶│  ─ /cf  → cloudflare│   └─────────────────┘
│   └ секреты ┘   релей          │   │                     │──▶  DNS вашей зоны
└────────────────────────────────┘   └─────────────────────┘
```

**На VPN-сервере не появляется ни одного скрипта и ни одного ключа.** Машина,
которую с наибольшей вероятностью будут ковырять, не хранит доступов вообще.

### Может ли ТСПУ заблокировать вас по домену

Домена в вашем трафике нет: AmneziaWG — обфусцированный UDP без SNI, Reality
предъявляет чужой SNI. Заблокировать домен по SNI-инспекции не за что.

Домен виден только когда клиент его резолвит. Чтобы попасть в реестр, домен надо
найти, и есть три пути, из которых один неочевидный: **Certificate
Transparency** — любой выпущенный на домен TLS-сертификат уходит в публичные
CT-логи и находится через crt.sh за минуту. Reality сертификат не требует —
**не выпускайте сертификат на VPN-домен и на `*.вашазона`.** Остальные два пути:
публикация конфигов в открытых чатах и перебор поддоменов.

Порядок реальных угроз: блок `IP:порт` → блок по фингерпринту протокола → блок
домена. Ротация лечит первое, детектор специально учится отличать второе, а от
третьего страхует запасной домен в другой зоне у другого регистратора.

## Режимы смены адреса

| Режим | Даунтайм | Деньги | Меняет зону | Меняет подсеть | Нужен SSH |
|---|---|---|---|---|---|
| `replace-ip` | ~2–3 мин | нет | нет | нет | нет |
| `recreate` | ~5–10 мин, при переезде дольше | шаблон диска | **да** | **да** | нет |
| `floating` | **0** | адрес помесячно | нет | нет | да |

Точные шаги с вашими значениями показывает `/plan` в боте — включая, какой
сервер, какой диск, сколько продлится и во что обойдётся.

### `replace-ip` — рабочая лошадка

Стоп → новый IPv4 на MAC существующего интерфейса → освободить старый → старт.
При загрузке адрес приезжает по DHCP, netplan трогать не нужно.

Порядок «сначала выдать новый, потом освободить старый» не косметический:
наоборот интерфейс на секунду остаётся без адресов. Если освободить старый не
удалось, сервер всё равно поднимается, **DNS не трогается**, приходит алерт.

### `recreate` — когда выжжена подсеть или нужен переезд

Стоп → шаблон системного диска → новый сервер из шаблона → обновить DNS →
удалить старый.

Шаблон тянет за собой **всё**: ключи AmneziaWG и Reality, базу клиентов, swap,
SSH host key и `authorized_keys`. Клиентские конфиги после пересоздания остаются
валидными — меняется только адрес.

Старый сервер удаляется **после** того, как новый поднялся и DNS переписан.
Если что-то сорвалось раньше — старый просто запускается обратно. Последний
шаблон сохраняется как точка отката (`/rollback`).

Кросс-зонный переезд: диск клонируется в целевую зону (`POST
/1.3/storage/{uuid}/clone` с параметром `zone`), там из него делается шаблон, и
уже из него поднимается сервер. Это самый долгий шаг, полчаса — норма.

### `floating` — если даунтайм неприемлем

Плавающий адрес заказывается на **живом** сервере, поднимается по SSH через
`/etc/netplan/99-floating.yaml` + `netplan apply`, соединение не рвётся.

Оговорка: агент ходит на сервер по SSH, и если заблокирован сам адрес, то и SSH
до него не достучится. Режим рассчитан на профилактическую ротацию до блокировки
и на случай, когда закрыт только рабочий порт, а 22-й жив — ровно то, что
детектор и различает. Агент пробует по очереди текущий плавающий, основной и
IPv6; если молчат все — честно отказывается.

### `auto` — лестница эскалации

1. Первая блокировка → `replace-ip`.
2. Новый адрес умер меньше чем за `escalate_after_hours` → дело не в адресе, а в
   подсети → `recreate` в следующую зону из `zone_rotation`.
3. Заблокировано и после переезда → **стоп**. Дальше гонять адреса бессмысленно:
   приходит алерт с предложением менять порт, `dest`/SNI Reality или транспорт.

## Деньги

Подробности в боте: `/guide_money`.

- **`replace-ip` — бесплатно.** Новый адрес выдаётся на время остановки, старый
  освобождается. Постоянно у сервера остаётся один адрес, включённый в план.
- **`recreate` — бесплатно по адресам, но платно по шаблону.** Новый сервер
  получает адрес бесплатно, а неиспользованное время старого возвращается на
  счёт: тарификация почасовая. Однако шаблон диска — это отдельное хранилище
  сверх квоты плана, и оно [тарифицируется по ГБ в час][storage-billing], пока
  существует. По умолчанию хранится один шаблон как точка отката; `keep_templates = 0`
  удаляет шаблоны сразу после успешного переезда — дешевле, но откатиться некуда.
- **`floating` — платно** за каждый зарезервированный адрес, пока он числится за
  аккаунтом, даже не привязанный к серверу.
- **IPv6 бесплатен**, по одному адресу на сервер.
- **Резервные копии UpCloud не используются и не включаются.** Платные
  Simple/Flexible Backups включать не нужно.

[storage-billing]: https://upcloud.com/docs/products/block-storage/billing/

## Установка

### Шаг 1. Релей

```bash
cd relay
export CF_DEPLOY_TOKEN=$(cat ~/.cf-deploy-token)
./deploy.sh relay.example.net
```

Скрипт заливает воркер, кладёт `RELAY_KEY` секретом, создаёт проксируемую
DNS-запись под маршрут, привязывает маршрут и проверяет, что `/healthz` отвечает
`ok` с ключом и `403` без него. Нужен только `curl` и `python3` — `wrangler` и
node не требуются, но поддержаны: см. [relay/README.md](relay/README.md).

Токен для развёртывания — отдельный, с правами `Workers Scripts: Edit`,
`Workers Routes: Edit`, `DNS: Edit`, `Zone: Read`; **после развёртывания
отзовите его**.

Два обязательных условия: **отдельный домен** (не тот, что обслуживает VPN —
иначе блокировка домена выносит разом и VPN, и канал управления) и **не
`*.workers.dev`** (его в России регулярно режут).

### Шаг 2. Агент

```bash
git clone https://github.com/UIbodulloev/vpn-ip-rotator.git
cd vpn-ip-rotator && sudo ./install.sh
```

Установщик создаёт системного пользователя `vpnrotator`, venv в
`/opt/vpn-rotator`, юнит systemd и спрашивает четыре бутстрап-значения:
`RELAY_URLS`, `RELAY_KEY`, `TG_BOT_TOKEN`, `TG_ADMIN_ID`. Ничего из уже
работающего на сервере он не трогает. Стартует с `dry_run = true`.

### Шаг 3. Доступы — из чата

`/setup` ведёт по шагам и показывает прогресс. Руками вы печатаете **только два
токена**, всё остальное выбирается кнопками из того, что вернул API.

```
⚙️ Настройка
▰▰▰▰▰▱▱▱▱▱  2 из 4

✅ 1. Токен UpCloud
✅ 2. Сервер  (203.0.113.11)
▫️ 3. Токен Cloudflare
▫️ 4. Домен и DNS-запись

[ ▶️  Дальше: Токен Cloudflare ]
```

| Шаг | Что делаете |
|---|---|
| 1. Токен UpCloud | присылаете токен, бот сразу его проверяет |
| 2. Сервер | **жмёте кнопку** — бот показал список серверов аккаунта |
| 3. Токен Cloudflare | присылаете токен, бот проверяет |
| 4. Домен и запись | **жмёте кнопку** — бот показал зоны, потом A-записи; домен и AAAA подставляются сами |

Обязательных ключей четыре. Необязательные спрятаны за отдельной кнопкой и
каждый подписан, что включает: админ-токен UpCloud (чтобы `recreate` работал под
субаккаунтом), логин субаккаунта, AAAA-запись, приватный SSH-ключ (только для
`floating`) и публичный SSH-ключ.

Где брать токены и с какими правами — `/guide_where`. Сообщение с токеном бот
удаляет сразу после чтения; полностью без чата — `rotator setup --local`.

> **Настраивайте в личном чате, а не в группе.** У ботов Telegram по умолчанию
> включён режим приватности: в группах бот получает только команды, а обычный
> текст ему не доставляется вообще. Выглядит это так, будто команды работают, а
> присланный токен пропадает. Подробности и обход — `/guide_chats`.

### Шаг 4. Клиенты — один раз до первой ротации

**Без этого шага смена DNS ничего не переключит.** Приложение Amnezia принимает
только IPv4 при добавлении сервера ([issue #948][i948] закрыт как «not
planned»), поэтому домен подставляется в конфиги руками — один раз.

[i948]: https://github.com/amnezia-vpn/amnezia-client/issues/948

1. **AmneziaWG** — заменить адрес на домен: `Endpoint = vpn.example.com:35206`
2. **VLESS Reality** — заменить хост в ссылке, SNI не трогать:
   ```
   vless://<uuid>@vpn.example.com:443?security=reality&sni=www.googletagmanager.com&fp=chrome&pbk=<public-key>&sid=<short-id>&flow=xtls-rprx-vision&type=tcp#vpn
   ```
   Публичный ключ Reality: `docker exec amnezia-xray xray x25519 -i <privateKey>`
3. **TTL A-записи — 60**, не `Auto`. Proxy выключен: через оранжевое облако VPN
   не ходит.
4. Раздайте каждому **два** конфига: основной по домену и запасной по IP.
5. Заведите запасной домен в другой зоне у другого регистратора.

После этого шага конфиги больше не меняются никогда.

### Шаг 5. Боевой режим

Когда `/check` зелёный и проверки пройдены — уберите `dry_run` в
`/etc/vpn-rotator/config.toml`, `systemctl restart vpn-rotator`, `/mode auto`.

## Как проверить

Три уровня, от безопасного к боевому. В боте: `/guide_testing`.

### Ничего не выполняется

| Команда | Что показывает |
|---|---|
| `/plan` | точные шаги каждого режима с вашими значениями, длительность, цена |
| `/simulate` | что сделала бы автоматика прямо сейчас, держат ли предохранители |
| `/probe` | пробы и вердикт |
| `/ip` | сошлись ли адрес сервера и DNS-запись |

### Репетиция с `dry_run`

Ротация не выполняется, но ведёт себя как настоящая: пишется в историю, включает
cooldown и дневной лимит, сбрасывает серию неудач. Так проверяется детектор.

```bash
sudo iptables -A OUTPUT -d АДРЕС -p tcp --dport 443 -j DROP
sudo iptables -A OUTPUT -d АДРЕС -p tcp --dport 22  -j DROP
```

Через ~5 минут должен прийти вердикт «блокировка IP». Снимите правила теми же
командами с `-D` вместо `-A`.

**Обязательно повторите, зарезав только 443, оставив 22.** Вердикт обязан стать
«блок порта/протокола», и ротация **не** предлагается. Это ровно то, что
защищает от бессмысленного сжигания адресов.

### Боевой прогон

Единственный способ убедиться, что режим отработает — выполнить его руками в
удобное время, от безопасного к серьёзному:

1. `/rotate` → `replace-ip` — 2–3 минуты, бесплатно, легко повторить.
2. `/rotate` → `recreate` в свою зону — проверяет шаблон и то, что **старые
   конфиги клиентов продолжают работать**.
3. `/rotate` → `recreate` в другую зону — самый долгий, проверяет переезд.

После каждого: `/ip` покажет, сошлись ли адрес и DNS; `dig +short ваш.домен
@1.1.1.1` отдаёт новый адрес; клиенты подключаются **без правки конфигов**.

Совсем без риска для рабочего VPN: создайте в UpCloud копеечный сервер,
переключите на него `SERVER_UUID` через `/setup`, прогоните все режимы, потом
верните обратно.

### Тесты кода

Гоняются без единого реального доступа, на фейковых UpCloud, Cloudflare и Telegram:

```bash
python3 -m unittest discover -s tests -v
```

## Детектор

Опрашивает VPN **раз в минуту** и требует **пять неудач подряд** — на решение
уходит около пяти минут. Четыре пробы первого уровня:

| Проба | Смысл |
|---|---|
| **S** — свой канал | TCP до Яндекса. Не прошло — молчим, это ваш интернет |
| **A** — рабочий порт | TCP до `IP:443` |
| **B** — контрольный порт | TCP до `IP:22` |
| **C** — состояние сервера | `GET /1.3/server/{uuid}` через релей |

Вердикты:

- A ❌, B ❌, сервер `started` → **блокировка IP** → ротация
- A ❌, B ✅ → **блок порта/протокола** → алерт, ротации нет
- сервер не `started` → **сервер лежит** → алерт, ротации нет
- контрольный порт отключён → вердикт помечается неуверенным, автоматика не
  запускается

**Уровень 2** — настоящая сессия вместо голого TCP. Единственный способ поймать
фингерпринт-блок, когда порт открывается, а соединение рвётся:

```toml
[detector]
deep_probe = true
reality_probe_cmd = "curl -sf --max-time 15 --proxy socks5h://127.0.0.1:10808 https://www.gstatic.com/generate_204"
awg_probe_cmd = "/opt/vpn-rotator/bin/awg-handshake-check.sh probe0"
```

**Уведомления** приходят, когда: набран порог и запускается ротация (плюс отчёт
по каждому шагу); связь восстановилась; вердикт не лечится сменой адреса (не
чаще раза в час); предохранитель не дал запустить ротацию. Пока порог не набран,
бот молчит.

**Предохранители:** пять неудач подряд вместо одной, `cooldown_hours = 6`,
`max_per_day = 2`, `/pause`, история с причиной и снимком проб.

## Файлы и настройки

```
/opt/vpn-rotator/            код и venv
/etc/vpn-rotator/config.toml настройки            (0640)
/etc/vpn-rotator/secrets.env доступы              (0600, владелец vpnrotator)
/var/lib/vpn-rotator/state.json  состояние и история
```

`state.json` пишется **после каждого шага** ротации. Падение посреди `recreate`
доигрывается с места остановки — на старте агент делает это сам и громко
предупреждает.

Юнит запускается под отдельным пользователем с `ProtectSystem=strict`,
`PrivateTmp`, `NoNewPrivileges` и белым списком семейств сокетов.

`install.sh` **не перезаписывает существующий `config.toml`** — новые параметры
после обновления смотрите в `config.example.toml`.

## Если что-то не работает

| Симптом | Причина | Что делать |
|---|---|---|
| Бот отвечает на команды, но не видит обычный текст | Режим приватности Telegram в группах | Настраивайте в личном чате, либо `@BotFather` → `/setprivacy` → Disable и **переподключите бота к группе** |
| Сообщения доходят «через одно» | Два процесса с одним токеном тянут `getUpdates` | `pgrep -af 'rotator run'`, убить лишний. Бот пишет об этом в журнал сам |
| `сообщение от постороннего чата N` | В `TG_ADMIN_ID` не тот чат | Бот пришлёт кнопку «разрешить чат N»; принимает несколько ID через запятую |
| `pip: No such file or directory` при установке | Нет пакета `python3-venv` | Обновите репозиторий: установщик ставит его сам и пересоздаёт битый venv |
| Бот молчит после присланного значения | Значение не похоже на токен | Бот отвечает распиской на любое сообщение и объясняет, что не так |
| Опрос срывается | Слишком длинный long-poll через воркер | Длина ограничена 25 с в коде независимо от конфига |

Первым делом — **`/diag`**: версия, PID, разрешённые чаты, режим приватности,
какое поле бот ждёт, состояние каналов и хвост журнала. Затем
`journalctl -u vpn-rotator -f`.

## Чего это не решает

- **Фингерпринт-блок протокола.** Новый адрес отваливается за минуты. Лечится
  сменой порта, `dest` и SNI Reality, транспорта (XHTTP), параметров обфускации
  AmneziaWG. Детектор распознаёт этот случай и ротацию не запускает.
- **Блок подсети целиком.** Внутри одной подсети ротация бессмысленна; ответ —
  `recreate` в другую зону.
- **Режим белых списков.** Если ТСПУ переключат на allow-list, не спасёт ни один
  из этих протоколов.
- **Одна точка наблюдения.** РФ-хостинг и домашние провайдеры фильтруются
  по-разному.

## Доверие и границы

Токены проходят транзитом через ваш воркер, где TLS терминируется на стороне
Cloudflare. Свой DNS вы Cloudflare уже доверяете, так что порог не меняется — но
сказать об этом прямо честнее, чем умолчать. Воркер секретов не хранит.

Секреты на российском сервере защищены правами `0600` и изоляцией systemd — не
шифрованием: ключ для расшифровки всё равно пришлось бы держать рядом. Реальная
защита здесь — узкие права токенов: субаккаунт на один сервер и токен Cloudflare
на одну зону с одним правом.
